Файл `labs/lab02/data/data_v07/activity.csv` — CSV із заголовком і колонками:

| Колонка     | Опис                                              |
|-------------|---------------------------------------------------|
| `Timestamp` | час дії у форматі ISO 8601 без пояса (`2026-09-21T23:40:00`) |

## Запуск

### Завдання 1: демонстрація класів

```powershell
python -m labs.lab02.main demo
```

Показує успішний і невдалий вхід, зміну email із перевіркою, права
адміністратора, доступ через `account[...]`, завершення сеансу за таймаутом
(час імітується зсувом `last_activity`), вихід із системи та журнал аудиту.
Хешування пароля (600 000 ітерацій PBKDF2) займає близько секунди загалом.

### Завдання 2: аналіз журналу

```powershell
python -m labs.lab02.main analyze `
    --activity-log labs/lab02/data/data_v07/activity.csv `
    --after-hours `
    --out-report labs/lab02/data/off_hours_audit.json `
    --log-file labs/lab02/data/activity_audit.log
```

Мінімальний запуск (без позаробочої активності, звіт поруч із журналом):

```powershell
python -m labs.lab02.main analyze --activity-log labs/lab02/data/data_v07/activity.csv
```

### Параметри `analyze`

| Параметр | Обов'язковий | За замовчуванням | Опис |
|----------|--------------|------------------|------|
| `--activity-log` | так | — | шлях до CSV-журналу |
| `--after-hours` | ні | вимкнено | прапорець: виявляти дії з 22:00 до 06:00 та у вихідні |
| `--out-report` | ні | `off_hours_audit.json` поруч із журналом | шлях до JSON-звіту |
| `--log-file` | ні | лише консоль | файл, у який дублюються логи (з часовими мітками) |
| `--critical-prefix` | ні | `/prod`, `/finance`, `/admin` | каталог критичних ресурсів (можна повторювати) |
| `--mass-threshold` | ні | 10 | мінімум звернень до критичних ресурсів для тривоги |
| `--mass-window-min` | ні | 60 | розмір ковзного вікна, хвилин |

Числові параметри перевіряються на рівні `argparse` (ціле число > 0), тому
некоректне значення дає повідомлення про помилку й код завершення 2 ще до
початку аналізу.

## Що саме виявляє утиліта

1. **Позаробочий час** (лише з `--after-hours`): дії з 22:00 (включно) до
   06:00 (не включно) та в суботу й неділю. Для кожної події у звіті вказано
   причину (`night`, `weekend`) і чи зачіпає вона критичний ресурс.
2. **Масові звернення до критичних ресурсів** (завжди): користувач, який за
   будь-яке ковзне вікно в `--mass-window-min` хвилин мав щонайменше
   `--mass-threshold` звернень до критичних ресурсів. У звіті — найбільше
   вікно користувача: кількість, межі, ресурси та IP.

Дії групуються за користувачами через `collections.defaultdict(list)`.

## Результати

Консоль і лог-файл: рівні `INFO` (хід роботи), `WARNING` (пропущені рядки),
`ERROR` (збої) та власний рівень `ALERT` для тривог. JSON-звіт містить
розділи `meta`, `off_hours_events` і `mass_access_alerts`.

На даних варіанта 7 з параметрами за замовчуванням утиліта знаходить 5 дій у
позаробочий час (u002, u003, u005, u001, u003) і одну масову аномалію (u007:
18 звернень до критичних ресурсів за 34 хвилини).

## Поведінка при помилках

| Ситуація | Реакція | Код завершення |
|----------|---------|----------------|
| файл журналу не знайдено / немає прав / не читається | `ERROR`, аналіз не починається | 1 |
| відсутні обов'язкові колонки або порожній файл | `ERROR` із переліком колонок | 1 |
| рядок із некоректним часом, порожніми полями або часовим поясом | `WARNING`, рядок пропускається, обробка триває | 0 |
| не вдалося створити лог-файл | `WARNING`, логування лише в консоль | 0 |
| не вдалося записати звіт | `ERROR` | 1 |
| некоректні аргументи командного рядка | повідомлення `argparse` | 2 |

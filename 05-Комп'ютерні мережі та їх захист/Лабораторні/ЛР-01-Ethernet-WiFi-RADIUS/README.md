## 0. Що це за робота одним абзацом

Фактично це **три роботи в одній**:

1. **Провідна мережа** за індивідуальним варіантом — ланцюг із 5 мережевих пристроїв (HUB/SW/BRG/RPT), з'єднаних лініями різних специфікацій Ethernet (100Base-TX, 100Base-FX, 1000Base-T, 1000Base-F). До двох крайніх пристроїв — по 4 ПК.
2. **Вимірювання якості** — ping -n 200 + Traffic Generator, фіксуємо втрачені пакети. Потім замінюємо пристрої **фізичного рівня** (HUB, RPT) на пристрої **канального рівня** (SW, BRG) і повторюємо. Мета — показати числом, що домен колізій зменшився.
3. **Wi-Fi** — 3 бездротові сегменти по 4 ПК, під'єднані до провідної мережі, ті самі вимірювання + захист (WPA2, за бажанням — RADIUS).

Все в Cisco Packet Tracer. Здається як звіт зі схемами й скріншотами.

## 1. Індивідуальне завдання: як читати таблицю варіантів

Рядок варіанта в Додатку читається як **ланцюжок**:

```
[Пристрій1] --лінія1-- [Пристрій2] --лінія2-- [Пристрій3] --лінія3-- [Пристрій4] --лінія4-- [Пристрій5]
```

Приклад (варіант 1):

```
SW --1000Base-T-- SW --1000Base-T-- BRG --100Base-FX-- HUB --100Base-TX-- HUB
```

Під рядком — діапазон IP-адрес для всіх ПК мережі.

Скорочення:

| Позначення | Пристрій у PT | Рівень OSI | Домени колізій |
|---|---|---|---|
| HUB | Hub-PT | 1 (фізичний) | один спільний на всі порти |
| RPT | Repeater-PT | 1 (фізичний) | один спільний, 2 порти |
| SW | Switch-PT (або 2950-24) | 2 (канальний) | окремий на кожен порт |
| BRG | Bridge-PT | 2 (канальний) | окремий на кожен порт, 2 порти |

**Наслідок для п.5 завдання:** «замінити пристрої фізичного рівня на пристрої канального» = HUB → SW, RPT → BRG (або SW). Саме цю заміну і вимірюємо.

## 2. Специфікація лінії → кабель і модуль у Packet Tracer

Це головна технічна пастка роботи. Специфікація з варіанта задає **і тип кабелю, і тип порту**.

| Специфікація | Середовище | Швидкість | Кабель у PT | Модуль на обох пристроях |
|---|---|---|---|---|
| 100Base-TX | вита пара UTP cat5 | 100 Мбіт/с | Copper Straight/Cross | стандартний FastEthernet (`...-NM-1CFE`) |
| 100Base-FX | багатомодове оптоволокно | 100 Мбіт/с | **Fiber** | `...-NM-1FFE` |
| 1000Base-T | вита пара UTP cat5e | 1 Гбіт/с | Copper Straight/Cross | `...-NM-1CGE` |
| 1000Base-F (SX/LX) | оптоволокно | 1 Гбіт/с | **Fiber** | `...-NM-1FGE` |

**Як міняти модуль у PT:**
1. Клік на пристрій → вкладка **Physical**.
2. **Вимкнути живлення** — тумблер на зображенні пристрою (без цього модуль не встановиться).
3. Витягнути наявний модуль зі слота мишкою в список ліворуч.
4. Перетягнути потрібний модуль зі списку в порожній слот.
5. Увімкнути живлення назад.

**Прямий чи перехресний кабель (мідь):**
- ПК ↔ HUB/SW/BRG → **Copper Straight-Through**
- HUB ↔ HUB, HUB ↔ SW, SW ↔ SW, SW ↔ BRG, будь-яка пара мережевих пристроїв → **Copper Cross-Over**
- Правило: однакові за роллю порти (обидва MDI або обидва MDI-X) → crossover.
- Якщо лінк не піднявся (червоні трикутники) — перша гіпотеза саме тут.

Оптика (Fiber) типом не ділиться — але модулі мають бути оптичні з **обох** боків.

## 3. IP-адресація

Уся мережа з HUB/SW/BRG — це **один широкомовний домен**, маршрутизації немає. Отже:

- Усі ПК (провідні + бездротові) — в **одній підмережі**, з діапазону варіанта.
- Маска — /24 (255.255.255.0), якщо викладач не вимагає інакше.
- Шлюз не потрібен — виходу за межі мережі немає.

**Пастки:**
- Якщо діапазон починається з `.0` (напр. `192.168.5.0 ÷ 192.168.5.25`) — `.0` це **адреса мережі**, хосту не призначається. Починати з `.1`.
- У деяких варіантах у методичці явна помилка в діапазоні (напр. вар. 4: `172.16.36.16 ÷ 172.16.35.39` — різні треті октети). Якщо це твій варіант — питати викладача, не вгадувати.
- Адрес у діапазоні (~26) вистачає на 8 провідних + 12 бездротових = 20 ПК. Розписати розподіл **до** того, як почнеш клікати.

Таблиця адрес (заповнити під свій варіант):

| Пристрій | Сегмент | IP | Маска |
|---|---|---|---|
| PC0 | провідний, лівий край | | 255.255.255.0 |
| ... | | | |

## 4. План виконання по блоках

### Блок A — провідна мережа за варіантом (п.1–2 завдання)

1. Виписати ланцюжок свого варіанта явно, з номерами ліній.
2. Розставити 5 пристроїв, підписати їх (Display name).
3. Для кожної лінії поставити правильні модулі з обох боків **до** з'єднання кабелем.
4. З'єднати лінії. Дочекатися зелених маркерів (STP на SW може «думати» ~30 с).
5. До двох **крайніх** пристроїв підключити по 4 ПК (Copper Straight-Through).
6. Призначити IP статично: PC → Desktop → IP Configuration → Static.
7. Перевірка: ping з кожного ПК лівого краю на ПК правого краю.

**Контроль:** має пінгуватися **все з усім** — маршрутизації немає, але й меж підмереж немає.

### Блок B — вимірювання на «фізичній» топології (п.3–4)

8. На двох протилежних ПК запустити Traffic Generator (Desktop → Traffic Generator) — паразитний трафік:
   - Select Application: PING
   - Destination / Source IP: адреси відповідних ПК
   - TTL 32, TOS 0, Sequence Number 1
   - Size: 1400–2500 байт (більший пакет = більше навантаження)
   - Simulation Settings: **Periodic**, Interval 0.1–0.3 с
   - Send — і **не закривати вікно**, інакше потік обірветься.
9. Одночасно з іншої пари ПК: `ping -n 200 <IP крайнього ПК>`.
10. Зафіксувати рядок статистики: `Sent = 200, Received = ..., Lost = ... (..% loss)`. **Скріншот.**
11. Зупинити всі генератори (Stop).

### Блок C — заміна на канальний рівень (п.5)

12. Замінити HUB → SW, RPT → BRG. Модулі й кабелі — ті самі специфікації!
13. Повторити Блок B з **тими самими** параметрами (це важливо: порівнюємо однакові умови).
14. Порівняти втрати. Очікуваний результат — істотно менше (у методичці: 6 → 1 пакет).

**Пояснення для висновку:** hub ретранслює кадр у всі порти → один домен колізій на всю мережу → при одночасній передачі кадри накладаються, CSMA/CD змушує передавати повторно → втрати. Switch має таблицю MAC-адрес і комутує кадр лише в потрібний порт → домен колізій на кожен порт окремо → колізій між парами, що не перетинаються, немає.

### Блок D — Wi-Fi (п.6–11)

15. Три бездротові сегменти. **Рекомендація:** брати `AccessPoint-PT`, а не `WRT300N`.
    - AccessPoint-PT — це міст (L2): усі бездротові ПК лишаються в тій самій підмережі, що й провідні.
    - WRT300N — це роутер з NAT і DHCP: він створить окрему підмережу, і наскрізний ping доведеться окремо розбирати. Якщо викладач не вимагає саме роутер — не ускладнювати.
16. У кожен ПК бездротового сегмента вставити Wi-Fi-адаптер: Physical → вимкнути живлення → витягнути мідний модуль → вставити `PT-HOST-NM-1W` (або `WPC300N` для варіанта з роутером) → увімкнути.
17. Налаштувати точки доступу: Config → Port 1 → SSID.
    - Різні SSID для трьох сегментів (WIFI-1 / WIFI-2 / WIFI-3).
    - Канали **1, 6, 11** — це три неперекривні канали діапазону 2.4 ГГц. Окремий бал у висновку.
18. Кожну точку доступу під'єднати Copper Straight-Through до провідної мережі (порт 0 AP → порт HUB/SW).
19. IP бездротовим ПК — статично, з того ж діапазону.
20. Тести (п.8): `ping -n 200` між двома крайніми ПК **одного** сегмента; потім між ПК **різних** сегментів. Зафіксувати втрати.
21. Навантаження (п.9): Traffic Generator на 2 центральних ПК кожного сегмента, повторити п.20.
22. Захист (п.11): Config → Port 1 → Authentication:
    - Мінімум: **WPA2-PSK**, Encryption Type **AES**, ключ ≥ 8 символів — на всіх трьох точках.
    - Для повного балу: на одній точці — **WPA2 Enterprise** + сервер RADIUS:
      - Server-PT → Services → **AAA** → Service: On, RADIUS Port 1645
      - Network Configuration: Client Name = ім'я точки доступу, Client IP = її IP, Server Type = Radius, Key = спільний секрет
      - User Setup: логіни/паролі користувачів
      - На точці доступу: RADIUS Server IP = IP сервера, Shared Secret = той самий ключ
      - На ПК: User ID + Password замість ключа.
    - **Доказ захисту:** скріншот того, що ПК без ключа/облікових даних **не** під'єднується. Без цього п.11 не зарахований — вимога звучить «забезпечити захист», отже треба показати, що він працює.

## 6. Контрольні запитання (16 шт.)

Відповіді на 1–10 повністю є в методичці (розділ 1), на 11–15 — у розділі 2. Питання 16 — власна аргументація.

1. Відмінність фізичної й логічної топологій.
2. Які фізичні топології застосовуються в LAN Ethernet.
3. Що таке мережева технологія.
4. Що таке колізія, її причина, що таке домен колізій.
5. Варіанти кабельних систем фізичного рівня Fast Ethernet.
6. Як змінився міжкадровий інтервал Fast Ethernet відносно Ethernet і чому.
7. Призначення режиму автопереговорів; специфікації найнижчого й найвищого пріоритету.
8. Типи фізичного середовища за 802.3z.
9. Що в Gigabit Ethernet на витій парі cat5 дає 1000 Мбіт/с (PAM5, 4 пари, 125 МГц).
10. Специфікації 10G Ethernet на оптоволокні.
11. Стандарти побудови Wi-Fi.
12. Переваги й недоліки Wi-Fi.
13. На яких рівнях ISO/OSI працює 802.11.
14. Різниця WPA2 Personal та WPA2 Enterprise.
15. Протоколи безпеки Wi-Fi.
16. Яке обладнання обрав би для SOHO; а для Wi-Fi мережі кафедр ЗІ та БІТ.

## Пояснення до розмітки `index.html`

Сторінка побудована **тільки на структурі**: жодного `style`, жодного `<script>` — цього вимагає методичка на цьому етапі.

**Обов'язковий каркас документа**

- `<!DOCTYPE html>` — перемикає браузер у стандартний режим (без нього вмикається quirks mode зі старими правилами відображення);
- `<html lang="uk">` — корінь документа; атрибут `lang` потрібен скрінрідерам і пошуковим системам;
- `<head>` — метадані, які не відображаються на сторінці: `charset`, `viewport`, `description`, `title`;
- `<body>` — усе, що бачить користувач.

**Семантичні теги і що вони означають у цьому резюме**

| Тег | Роль на сторінці |
|---|---|
| `<header>` | шапка: ім'я, посада, контакти, навігація |
| `<nav>` | блок навігаційних посилань-якорів на секції |
| `<main>` | основний унікальний вміст сторінки (на сторінці може бути лише один) |
| `<section>` | тематичний розділ із власним заголовком: «Профіль», «Досвід», «Освіта»… |
| `<article>` | самодостатня одиниця — одне місце роботи, один проєкт |
| `<address>` | контактні дані автора документа |
| `<time datetime="2022-10">` | дата у машинозчитуваному форматі |
| `<footer>` | підвал: контакти й копірайт |

Якби замість них скрізь стояв `<div>`, сторінка виглядала б **однаково**, але втратила б сенс для пошукових систем і програм екранного доступу. Саме в цьому цінність семантики.

**Заголовки.** Один `<h1>` (ім'я) → `<h2>` на кожну секцію → `<h3>` на кожну посаду/проєкт. Рівні не пропускаються — інакше ламається структура документа для скрінрідера.

**Блокові й рядкові елементи.** `<section>`, `<article>`, `<ul>`, `<p>` — блокові: займають усю доступну ширину й починаються з нового рядка. `<a>`, `<strong>`, `<small>`, `<time>` — рядкові: вбудовуються в потік тексту.

**Посилання.** Внутрішні відносні (`href="#profile"` — якір на секцію тієї самої сторінки) і зовнішнє абсолютне (`href="https://lpnu.ua"`) з `target="_blank" rel="noopener noreferrer"` — `noopener` не дає новій вкладці доступу до об'єкта `window` нашої сторінки.

**Фавікон** доданий через `<link rel="icon" href="data:image/svg+xml,...">` — SVG вбудовано прямо в атрибут, щоб не тягнути окремий файл.

## Питання для самоконтролю (Частина 1)

**1. Що таке HTML і для чого він використовується?**
HyperText Markup Language — мова розмітки, яка описує **структуру та зміст** документа для браузера за допомогою тегів. Вона не відповідає за оформлення (це CSS) і не за поведінку (це JavaScript).

**2. Яка структура типової HTML-сторінки? Які теги обов'язкові?**
`<!DOCTYPE html>` → `<html>` → `<head>` (із обов'язковими `<meta charset>` і `<title>`) → `<body>`. Формально обов'язковим є лише `DOCTYPE`, решту браузер добудує сам, але писати треба повний каркас.

**3. У чому різниця між блоковими та рядковими елементами?**
Блоковий (`div`, `p`, `section`) починається з нового рядка, займає всю ширину контейнера, приймає `width`/`height` та вертикальні відступи. Рядковий (`span`, `a`, `strong`) вбудований у текст, його ширина дорівнює вмісту, вертикальні `margin` на нього не діють.

**4. Що таке семантичні теги і чому вони важливі?**
Теги, назва яких описує призначення вмісту (`header`, `nav`, `main`, `article`, `footer`) на відміну від нейтрального `div`. Важливі для доступності (скрінрідери будують по них навігацію), SEO та читабельності коду.

**5. У чому різниця між обов'язковими та необов'язковими атрибутами?**
Без обов'язкового тег не виконує свою функцію або невалідний: `<img>` без `src` і `alt`, `<a>` без `href`. Необов'язкові уточнюють поведінку: `target`, `rel`, `title`, `loading="lazy"`.

**6. Для чого використовується тег `<meta>` і які атрибути містить?**
Задає метадані документа. Основні: `charset="UTF-8"` (кодування), `name="viewport" content="width=device-width, initial-scale=1.0"` (масштаб на мобільних), `name="description"` (опис для пошуковика), `name="author"`, `http-equiv`.

**7. Як працює тег `<link>` і які ресурси підключає?**
Оголошує зв'язок документа із зовнішнім ресурсом. Найчастіше: `rel="stylesheet"` (CSS), `rel="icon"` (фавікон), `rel="preload"` (попереднє завантаження), `rel="canonical"` (канонічна адреса).

**8. Різниця між абсолютними та відносними посиланнями?**
Абсолютне містить повну адресу з протоколом і доменом (`https://lpnu.ua/page`) і веде на конкретний ресурс в інтернеті. Відносне (`./styles.css`, `#profile`, `../img/a.png`) обчислюється від адреси поточного документа, тож проєкт можна перенести на інший домен без правок.

**9. Для чого атрибут `alt` у `<img>`?**
Текстова альтернатива зображення: її озвучує скрінрідер, вона показується, якщо картинка не завантажилась, і її індексує пошуковик. Для суто декоративних зображень ставиться порожній `alt=""`.

**10. Як правильно додати фавікон?**
`<link rel="icon" type="image/svg+xml" href="/favicon.svg">` у `<head>`. Браузери також автоматично шукають `/favicon.ico` у корені сайту. У цій роботі SVG вбудовано у `data:`-URL.

**11. Які основні теги використовуються у формах?**
`<form>` (обгортка з `action` і `method`), `<label>`, `<input>`, `<textarea>`, `<select>` + `<option>`, `<button>`, `<fieldset>` + `<legend>`.

**12. Які існують типи полів введення (`input type`)?**
`text`, `email`, `password`, `tel`, `number`, `url`, `date`, `time`, `checkbox`, `radio`, `file`, `range`, `color`, `hidden`, `submit`.

**13. Навіщо потрібні `name`, `value`, `placeholder`, `required`?**
`name` — ключ, під яким значення поля піде на сервер (без нього поле не надсилається); `value` — поточне/початкове значення; `placeholder` — підказка всередині порожнього поля (не замінює `label`); `required` — вмикає вбудовану браузерну валідацію «поле не може бути порожнім».

**14. Чому поля `label` корисні?**
`<label for="email">` пов'язує підпис із полем: клік по підпису фокусує поле (більша зона натискання), а скрінрідер озвучує призначення поля. Без `label` поле для незрячого користувача безіменне.

**15. Як працюють методи GET і POST?**
GET додає дані у рядок запиту URL (`?name=Dan`) — запит ідемпотентний, кешується, видно в історії, обмежений довжиною URL; підходить для пошуку й фільтрів. POST передає дані в тілі запиту — не кешується, не має обмеження довжини, підходить для створення записів і будь-яких приватних даних.

**16. Що таке валідація форми на стороні клієнта та сервера?**
Клієнтська (`required`, `type="email"`, `pattern`, JS) — миттєвий зручний зворотний зв'язок, але її легко обійти через DevTools або звичайний `curl`. Серверна — єдина, якій можна довіряти, бо виконується там, куди користувач не має доступу. Клієнтська потрібна для зручності, серверна — для безпеки.

**17. Як правильно розміщувати заголовки `<h1>`–`<h6>`?**
Один `<h1>` на сторінку, далі рівні за спаданням без пропусків. Заголовок обирається за місцем в ієрархії документа, а не за бажаним розміром шрифту — розмір задається через CSS.

**18. Які теги для вставки відео та аудіо?**
`<video>` і `<audio>` з атрибутами `controls`, `autoplay`, `muted`, `loop`, `preload`; усередині можна дати кілька `<source>` з різними форматами й текст-заглушку для старих браузерів. Для сторонніх плеєрів (YouTube) — `<iframe>`.

## Що саме зроблено

HTML-резюме з Частини 1 розбито на **логічні частини**, кожна стала окремим компонентом. У кожного компонента тіло — це розмітка з `index.html`, перенесена в JSX без змін у структурі й тексті:

| Компонент | Відповідає за | Тег(и) з Частини 1 |
|---|---|---|
| `Header.jsx` | ім'я, посада, контакти, навігація | `<header>` |
| `Profile.jsx` | блок «Профіль» | `<section id="profile">` |
| `Experience.jsx` | місця роботи | `<section id="experience">` |
| `Education.jsx` | освіта | `<section id="education">` |
| `Skills.jsx` | три групи навичок | `<section id="skills">` |
| `Languages.jsx` | володіння мовами | `<section id="languages">` |
| `Projects.jsx` | самостійні проєкти | `<section id="projects">` |
| `Footer.jsx` | контакти й копірайт | `<footer>` |

`App.jsx` лише збирає компоненти в порядку сторінки:

```jsx
function App() {
  return (
    <div>
      <Header />
      <main>
        <Profile />
        <Experience />
        <Education />
        <Skills />
        <Languages />
        <Projects />
      </main>
      <Footer />
    </div>
  );
}
```

**Чим JSX відрізняється від HTML у цій роботі** (це єдині правки при перенесенні):

- `datetime` → `dateTime` (атрибути пишуться в camelCase);
- коментарі `<!-- -->` не переносились;
- між текстом і тегом у кінці рядка JSX **з'їдає** пробіл, тому в `Profile.jsx` і `Footer.jsx` стоїть `{' '}` — інакше вийшло б «базою вC#» замість «базою в C#»;
- кожен компонент має один кореневий елемент і `export default`.

**Перевірка:** відрендерений React-вивід порівняно з `index.html` з Частини 1 — текст і теги з атрибутами збігаються, `npm run build` проходить без помилок.

## Питання для самоконтролю (Частина 2)

**1. Що таке React і яке його основне призначення?**
Бібліотека JavaScript для побудови інтерфейсів користувача. Призначення — описувати UI **декларативно**: ви описуєте, як інтерфейс має виглядати для поточного стану, а React сам приводить DOM до цього вигляду.

**2. Що таке компонент у React?**
Автономна функція, що повертає JSX і представляє частину інтерфейсу. Її можна використати повторно з різними даними. Назва компонента завжди з великої літери — саме так JSX відрізняє компонент від звичайного HTML-тега.

**3. Що таке JSX? Чим відрізняється від HTML?**
Синтаксичне розширення JavaScript, схоже на HTML. Відмінності: `class` → `className`, `for` → `htmlFor`, атрибути в camelCase (`onClick`, `tabIndex`), вирази в `{ }`, обов'язкове закриття всіх тегів (`<br />`), один кореневий елемент (або `<>…</>`). Браузер JSX не розуміє — Vite компілює його у виклики `React.createElement`.

**4. Що складає валідний React-компонент?**
Функція з іменем із великої літери, яка повертає JSX (або `null`), не змінює свої props і не викликає хуки умовно. Плюс експорт, щоб її можна було імпортувати.

**5. Як передавати дані між компонентами?**
Зверху вниз — через **props** (`<Header name="Danylo" />`, у компоненті — `function Header({ name })`). У цій роботі props не потрібні: компоненти статичні. Знизу вгору — через функцію зворотного виклику, передану в props. Для даних, потрібних багатьом компонентам, стан піднімають до спільного предка («lifting state up») або використовують Context.

**6. Яка роль файлів `main.jsx` та `App.jsx`?**
`main.jsx` — точка входу: знаходить `<div id="root">` у `index.html` і монтує в нього React-дерево через `createRoot(...).render(...)`. `App.jsx` — кореневий компонент застосунку, з якого починається власна структура UI.

**7. Чому важливо розбивати інтерфейс на компоненти?**
Повторне використання, ізоляція (помилка в `Footer` не ламає `Experience`), читабельність, простіше тестування, і React перемальовує лише той компонент, чиї дані змінилися.

**8. Що таке віртуальний DOM?**
Легке представлення UI у пам'яті у вигляді JS-об'єктів. При зміні стану React будує нове дерево, порівнює його з попереднім (reconciliation) і застосовує до реального DOM **лише різницю**. Це дешевше, бо операції з реальним DOM повільні.

**9. Як вивести динамічні дані в JSX?**
У фігурних дужках: `{name}`, `{new Date().getFullYear()}`, `{items.map(...)}`. (У цій роботі динамічних даних немає — текст написано прямо в JSX.) Всередині `{}` можна писати будь-який **вираз** (не інструкцію): тернарний оператор, виклик функції, `&&` для умовного рендерингу.

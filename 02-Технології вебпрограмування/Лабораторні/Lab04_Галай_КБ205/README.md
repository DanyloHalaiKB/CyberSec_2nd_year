# Частина 1. Vanilla JavaScript

## Завдання 1 — Збереження даних у браузері

`collectSystemInfo()` збирає 14+ параметрів ОС і браузера: `navigator.userAgent`,
`navigator.platform`, мови, кількість ядер, обсяг памʼяті, онлайн-статус, роздільну
здатність екрана, глибину кольору, часовий пояс, а також сучасний
`navigator.userAgentData` (назва й версія браузера без парсингу User Agent).

```js
localStorage.setItem('systemInfo', JSON.stringify(info));
```

**Чому `JSON.stringify`:** `localStorage` зберігає **лише рядки**. Якщо передати
об'єкт напряму, у сховище потрапить текст `[object Object]`. При зчитуванні —
зворотне перетворення `JSON.parse`.

`renderSystemInfo()` виводить у підвалі **весь** вміст `localStorage` (перебір через
`localStorage.length` + `localStorage.key(i)`), а не лише свій ключ — саме цього
вимагає завдання. Тому в підвалі видно і `systemInfo`, і збережену `theme`.

## Завдання 2 — Динамічний вміст із сервера

```js
const url = `https://jsonplaceholder.typicode.com/posts/${VARIANT}/comments`;
const response = await fetch(url);
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const comments = await response.json();
```

Два моменти, на яких найчастіше спотикаються:

1. **`fetch` не кидає помилку на 404 або 500.** Проміс відхиляється лише при мережевій
   помилці. Тому статус перевіряється вручну через `response.ok`.
2. Відгуки виводяться **в порядку отримання** — масив не сортується, індекс `index + 1`
   лише нумерує картки.

Елементи створюються через `document.createElement` і `textContent`, а не через
`innerHTML` із конкатенацією рядків. `textContent` автоматично екранує спецсимволи,
тому дані з чужого сервера не можуть виконатись як HTML/JS (захист від XSS).

## Завдання 3 — Форма зворотного зв'язку в модальному вікні

const MODAL_DELAY_MS = 60_000;   // 1 хвилина
setTimeout(openModal, MODAL_DELAY_MS);

## Завдання 4 — Перехід на нічний/денний режим

```js
function themeByTime() {
  const hours = new Date().getHours();     // 0–23
  return hours >= 7 && hours < 21 ? 'light' : 'dark';
}
```

- **Автоматично:** при завантаженні тема визначається за часом доби (день 07:00–21:00).
- **Вручну:** кнопка в навігації перемикає `body.dark-mode` і записує вибір у
  `localStorage`.
- **Пріоритет:** збережений ручний вибір > автовизначення.

У CSS нічна тема реалізована перевизначенням **лише CSS-змінних**:

```css
body.dark-mode {
  --accent: #c9a7ff;
  --surface: #1b1823;
  --bg: #121019;
  ...
}
```

Тобто не довелося дублювати жодного правила компонентів — вони автоматично беруть нові
значення токенів.

## Питання для самоконтролю (Частина 1)

**1. Що таке JavaScript і для чого використовується?**
Інтерпретована мова програмування з динамічною типізацією. У браузері відповідає за
поведінку сторінки: реакцію на події, зміну DOM, мережеві запити, роботу зі сховищами.
Поза браузером (Node.js) — за серверну логіку.

**2. Різниця між JavaScript і ECMAScript.**
ECMAScript — це **специфікація** мови (стандарт ECMA-262, версії ES6/2015, ES2020…).
JavaScript — її **реалізація** у конкретному рушії (V8 у Chrome/Node, SpiderMonkey у
Firefox) плюс API середовища (`document`, `fetch`, `localStorage`), яких у самій
специфікації немає.

**3. Способи підключення JS до HTML.**
Атрибут події в розмітці (`onclick="..."` — погана практика), вбудований `<script>…</script>`,
зовнішній `<script src="script.js">`. Для зовнішнього: без атрибутів — блокує розбір HTML;
`defer` — завантажується паралельно, виконується після побудови DOM, порядок файлів
зберігається (використано в роботі); `async` — виконується одразу після завантаження,
порядок не гарантований.

**4. Як оголошуються змінні?**
`const` — посилання не можна перепризначити (але вміст об'єкта/масиву змінювати можна);
`let` — змінна з блоковою областю видимості; `var` — застарілий варіант із функціональною
областю видимості й підйомом (hoisting). За замовчуванням `const`, `let` — коли значення
справді змінюється, `var` — не використовувати.

**5. Типи даних.**
Примітиви: `number`, `string`, `boolean`, `null`, `undefined`, `symbol`, `bigint`.
Усе інше — `object` (зокрема масиви, функції, `Date`, `Map`, `Set`). Примітиви
передаються за значенням, об'єкти — за посиланням.

**6. Чим відрізняються `null` і `undefined`?**
`undefined` — значення не присвоєно (змінна оголошена без значення, відсутній аргумент,
неіснуюча властивість). `null` — **навмисно** записана «порожнеча». Пастка:
`typeof null === 'object'` (історична помилка мови), тоді як `typeof undefined === 'undefined'`.
`null == undefined` → `true`, але `null === undefined` → `false`.

**7. Як перевірити тип змінної?**
`typeof x` для примітивів; `Array.isArray(x)` для масивів (бо `typeof []` дає `'object'`);
`x instanceof Date`; універсально — `Object.prototype.toString.call(x)`, що повертає
`[object Array]`, `[object Null]` тощо.

**8. Як правильно порівнювати значення?**
`===` і `!==` — строге порівняння без приведення типів. `==` виконує неявне приведення
і дає неочевидні результати: `'' == 0` → `true`, `'0' == 0` → `true`, `null == undefined` → `true`.
За замовчуванням завжди `===`.

**9. Як працює тернарний оператор?**
`умова ? значенняЯкщоTrue : значенняЯкщоFalse` — єдиний тернарний оператор у мові,
є **виразом** і повертає значення. У роботі:
`return hours >= 7 && hours < 21 ? 'light' : 'dark';`

**10. Як реалізувати умовне виконання коду?**
`if / else if / else`, `switch`, тернарний оператор, логічні скорочення `&&` і `||`,
оператор `??` (нульове злиття — спрацьовує лише на `null`/`undefined`, на відміну від `||`,
який реагує і на `0`, `''`, `false`), опціональний ланцюжок `?.` (у роботі:
`document.getElementById('themeToggle')?.addEventListener(...)`).

**11. Які існують цикли?**
`for` (відомо кількість ітерацій — використано для перебору `localStorage`), `while`,
`do…while` (тіло виконується хоча б раз), `for…of` (по значеннях ітерованого об'єкта),
`for…in` (по ключах об'єкта). Для масивів зручніші методи `forEach`, `map`, `filter`,
`reduce` — вони не дають випадково зіпсувати лічильник.

**12. Що таке `break` і `continue`?**
`break` повністю перериває цикл (а також вихід із гілки `switch`); `continue` пропускає
решту поточної ітерації й переходить до наступної. У `forEach` вони **не працюють** —
там для дострокового виходу потрібні `for…of`, `some()` або `every()`.

# Частина 2. Реалізація в React

| Задача | Компонент | Хуки |
|---|---|---|
| системна інформація у футері | `Footer.jsx` | `useState`, `useEffect([])` |
| відгуки з сервера | `Reviews.jsx` | `useState`, `useEffect([])` |
| модальна форма через 1 хв | `ContactForm.jsx` | `useState`, `useEffect([])`, `setTimeout` |
| перемикач теми | `App.jsx` + `ThemeToggle.jsx` | `useState`, `useEffect([theme])` |

## Ключові моменти реалізації

**Footer — `useEffect` як `componentDidMount`:**
```jsx
useEffect(() => {
  const data = { 'User Agent': navigator.userAgent, ... };
  localStorage.setItem('systemInfo', JSON.stringify(data));
  setInfo(JSON.parse(localStorage.getItem('systemInfo')));
}, []);   // ← порожній масив: рівно один раз при монтуванні
```

**Reviews — захист від оновлення демонтованого компонента:**
```jsx
useEffect(() => {
  let ignore = false;
  async function fetchComments() { ... if (ignore) return; setComments(data); }
  fetchComments();
  return () => { ignore = true; };   // функція очищення
}, []);
```
Стан `status` (`loading | ready | error`) керує умовним рендерингом через `&&`.

**ContactForm — таймер із обов'язковим прибиранням:**
```jsx
useEffect(() => {
  const timerId = setTimeout(() => setIsOpen(true), 60_000);
  return () => clearTimeout(timerId);   // ← без цього буде витік
}, []);
```
Прапорець `dismissed` не дає вікну відкритись повторно після закриття.

**Тема — стан + побічний ефект на DOM:**
```jsx
const [theme, setTheme] = useState(() => localStorage.getItem('theme') || themeByTime());

useEffect(() => {
  document.documentElement.classList.toggle('dark', theme === 'dark');
  localStorage.setItem('theme', theme);
}, [theme]);   // ← спрацьовує при кожній зміні теми
```

У Tailwind v4 керування темою за класом вмикається директивою в `src/index.css`:
```css
@custom-variant dark (&:where(.dark, .dark *));
```
після чого в компонентах працюють варіанти `dark:bg-slate-900`, `dark:text-slate-300`.

`ThemeToggle` отримує `theme` і функцію `onToggle` через props — це стандартний спосіб
передачі даних знизу вгору: дочірній компонент не змінює стан сам, а викликає передану
йому функцію.

## Питання для самоконтролю (React)

**1. Навіщо `useEffect` для отримання даних?**
Рендер компонента має бути **чистим**: лише обчислення JSX, без побічних ефектів. Запит
до мережі — побічний ефект. Якби `fetch` стояв прямо в тілі компонента, він виконувався б
при кожному рендері, а `setState` у відповіді спричинив би новий рендер → нескінченний цикл.
`useEffect` запускає такий код **після** рендеру й під контролем залежностей.

**2. Як масив залежностей `[]` впливає на виконання?**
Немає масиву — ефект після **кожного** рендеру. `[]` — рівно **один раз** при монтуванні
(і прибирання при демонтуванні). `[theme]` — при монтуванні та при кожній зміні `theme`.
React порівнює елементи масиву за `Object.is` із попереднім рендером.

**3. Чому `useState` замість звичайної змінної?**
Звичайна змінна всередині функції компонента створюється заново при кожному рендері —
її значення губиться. Ще важливіше: зміна звичайної змінної **не повідомляє React**, що
треба перемалювати компонент. `useState` і зберігає значення між рендерами, і запускає
повторний рендер при виклику сетера.

**4. Як запобігти повторному відкриттю модального вікна?**
Окремим станом-прапорцем: `const [dismissed, setDismissed] = useState(false)`, який
встановлюється в `close()` і перевіряється при рендері (`if (!isOpen || dismissed) return null`).
Для збереження між перезавантаженнями сторінки — `sessionStorage` (як у Частині 1) або
`localStorage`.

**5. Різниця між прямим маніпулюванням DOM і декларативним підходом React.**
Імперативно (`document.getElementById(...).innerHTML = ...`) ви описуєте **послідовність
кроків**, самі стежите за синхронізацією стану й розмітки — при зростанні кількості станів
це стає джерелом помилок. Декларативно ви описуєте, **як інтерфейс має виглядати для
поточного стану**, а React через віртуальний DOM сам обчислює мінімальну різницю й
застосовує її. Пряме звернення до DOM у React лишається винятком (`useRef`) — наприклад,
для фокусування поля чи вимірювання розмірів.

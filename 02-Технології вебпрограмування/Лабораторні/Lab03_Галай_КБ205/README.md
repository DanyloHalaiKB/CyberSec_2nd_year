# Частина 1. Вступ до CSS

## Вимога 1 — усі три способи підключення стилів, по одному разу

| Спосіб | Де в проєкті | Навіщо саме там |
|---|---|---|
| **Зовнішній** (external) | `<link rel="stylesheet" href="styles.css">` | ~400 рядків — уся основна стилізація. Файл кешується браузером і використовується всіма сторінками. |
| **Внутрішній** (internal) | блок `<style>` у `<head>` | правила, що стосуються лише цієї сторінки: `::selection` і `@media print`. |
| **Рядковий** (inline) | `style="letter-spacing: 0.04em;"` на `.header__role` | одне разове виняткове правило. Має найвищу специфічність, тому в реальних проєктах його уникають. |

Каскад тут працює так: зовнішній файл підключений **до** блоку `<style>`, тож при однаковій специфічності виграє внутрішній; inline перебиває обидва.

## Вимога 2 — селектори

| Тип | Приклад із `styles.css` | Специфічність |
|---|---|---|
| тег | `body`, `h1, h2, h3`, `ul`, `a`, `time` | 0-0-1 |
| клас | `.card`, `.entry__points`, `.tag--primary` | 0-1-0 |
| ID | `#profile .block__lead`, `#contacts` | 1-0-0 (+клас) |
| атрибут | `a[href^="mailto:"]`, `a[target="_blank"]`, `a[href="#top"]` | 0-1-0 |
| псевдоклас | `:hover`, `:focus-visible`, `:last-child`, `:first-child`, `:nth-child(even)` | 0-1-0 |
| псевдоелемент | `::before`, `::after`, `::selection` | 0-0-1 |

`a[href^="mailto:"]` — селектор «значення атрибута **починається з**»; завдяки йому іконка ✉ додається автоматично перед усіма поштовими посиланнями, і при додаванні нового контакту нічого правити не треба.

## Вимога 3 — явне керування блоковою моделлю

```css
html { box-sizing: border-box; }
*, *::before, *::after { box-sizing: inherit; }

.page {
  margin: 0 auto;                   /* зовнішній відступ: центрування */
  padding: var(--space-5);          /* внутрішній відступ */
  border: 1px solid var(--border);  /* рамка */
}
```

`box-sizing: border-box` означає, що `width` включає `padding` і `border`. Без нього блок `width: 100%` із `padding: 2rem` мав би реальну ширину `100% + 4rem` і вилазив би за межі контейнера.

## Вимога 4 — макет на Grid, а не на float

```css
.page {
  display: grid;
  grid-template-columns: 300px 1fr;
  grid-template-areas:
    "header  header"
    "sidebar content"
    "footer  footer";
  gap: var(--space-4);
}
```

Grid відповідає за **двовимірний** каркас сторінки (рядки + колонки), Flexbox — за **одновимірні** внутрішні блоки: шапка (`.header`), ряд навігації (`.nav__list`), хмара тегів (`.tags`), список мов (`.langs__item`). `float` не використовується ніде.

## Вимога 5 — медіазапит

```css
@media (max-width: 820px) {
  .page {
    grid-template-columns: 1fr;
    grid-template-areas: "header" "content" "sidebar" "footer";
  }
}
```

До 820 px сітка стає одноколонковою, **бічна панель переїжджає під основний вміст** (важливо: у HTML вона йде перед `<main>`, але Grid дозволяє змінити візуальний порядок без зміни розмітки), шапка вишиковується вертикально, відступи зменшуються.

## Питання для самоконтролю (Частина 1)

**1. Методи підключення CSS і різниця між ними.**
*Inline* (`style="..."`) — для одного елемента, найвища специфічність, не кешується, змішує стилі з розміткою. *Internal* (`<style>` у `<head>`) — для однієї сторінки, кешується разом із HTML. *External* (`<link>`) — окремий файл, кешується браузером, один файл на весь сайт; єдиний правильний варіант для основної маси правил.

**2. Різниця між селектором класу та ID.**
Клас (`.card`) можна застосувати до будь-якої кількості елементів, ID (`#profile`) має бути унікальним на сторінці. Специфічність ID (1-0-0) на порядок вища за клас (0-1-0), тому перевизначити ID-правило класом неможливо. Практика: стилізувати класами, а ID лишати для якорів і JavaScript.

**3. Що таке Box Model.**
Кожен елемент — прямокутник із чотирьох шарів: `content` → `padding` → `border` → `margin`. `padding` фарбується фоном елемента, `margin` — прозорий і між сусідніми блоками **схлопується** (collapse): два вертикальні відступи 20px і 30px дають 30px, а не 50px. `box-sizing: border-box` змінює, чи входять `padding` і `border` у задану `width`.

**4. Що таке специфічність.**
Вага селектора, яка вирішує конфлікт правил. Рахується трійкою (ID, класи/атрибути/псевдокласи, теги):

| Селектор | Вага |
|---|---|
| `p` | 0-0-1 |
| `.tag` | 0-1-0 |
| `a[target="_blank"]` | 0-1-0 |
| `.card .tag:hover` | 0-3-0 |
| `#profile .block__lead` | 1-1-0 |
| `style="..."` | 1-0-0-0 |
| `!important` | перебиває все |

За однакової специфічності виграє правило, оголошене **пізніше**.

**5. Як `display` і `position` впливають на позиціювання.**
`display` задає тип боксу: `block`, `inline`, `inline-block`, `flex`, `grid`, `none`. `position`: `static` (за замовчуванням), `relative` (зсув від власного місця, місце в потоці зберігається — використано для `.entry__points li` як контейнер для `::before`), `absolute` (від найближчого позиційованого предка, випадає з потоку), `fixed` (від вікна), `sticky` (гібрид relative/fixed).

**6. Flexbox чи Grid.**
Flexbox одновимірний — розподіляє елементи вздовж однієї осі, розмір елементів керує розкладкою. Grid двовимірний — ви спершу описуєте сітку (`grid-template-areas`), а потім розставляєте елементи по ній. Загальний каркас сторінки — Grid, внутрішні ряди/хмари елементів — Flex. У цій роботі використані обидва.

**7. Як працюють псевдокласи.**
Псевдоклас описує **стан** елемента, а не окремий елемент: `:hover` (курсор над елементом), `:focus` (елемент у фокусі), `:focus-visible` (фокус із клавіатури, але не від кліку миші — тому кільце фокуса не дратує користувачів миші, але залишається для доступності), `:active` (мить натискання), структурні `:first-child`, `:last-child`, `:nth-child(even)`. У роботі: `.nav__link:hover`, `a:focus-visible`, `.entry:last-child`, `.langs__item:nth-child(even)`.

**8. Як змінити стилізацію під різні пристрої.**
Медіазапитами (`@media (max-width: 820px)`), відносними одиницями (`rem`, `%`, `ch`, `vw`), функціями `clamp()` / `minmax()`, автоматичними сітками `repeat(auto-fit, minmax(...))`. Обов'язково `<meta name="viewport" content="width=device-width, initial-scale=1.0">`, інакше мобільний браузер відрендерить сторінку в «десктопну» ширину й зменшить її.

**9. Для чого властивості з префіксами (`-webkit-`, `-moz-`).**
Це вендорні префікси для експериментальних реалізацій властивостей, доки специфікація не стабілізувалась. Сьогодні більшість властивостей уже стандартні, тож префікси вручну **не пишуть** — за потреби їх додає autoprefixer на етапі збірки. Лишились рідкісні винятки (`-webkit-line-clamp`, стилізація скролбарів).

**10. Як організувати CSS, щоб він був читабельним.**
Змінні в `:root` для кольорів і відступів (у роботі — `--accent`, `--space-3`); єдина система іменування (тут BEM: `.card`, `.card__title`, `.tag--primary`); файл розбитий на пронумеровані блоки з коментарями-заголовками (токени → скидання → теги → макет → компоненти → ID/атрибути → псевдокласи → медіазапит); мінімум вкладеності й ID; жодного `!important`.

# Частина 2. Стилізація за допомогою Tailwind CSS

## Встановлення (Tailwind v4)

```bash
cd lab_2_react
npm install tailwindcss @tailwindcss/vite
```

`vite.config.js`:

```js
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
})
```

`src/index.css` — увесь попередній вміст видалено, лишився імпорт і власні токени:

```css
@import "tailwindcss";

@theme {
  --color-brand: #4c2a86;
  --color-brand-soft: #ede7f6;
  --color-ink: #1c1b1f;
  --font-display: "Segoe UI", system-ui, sans-serif;
}
```

Завдяки `@theme` зʼявляються класи `bg-brand`, `text-brand`, `border-brand-soft`, `font-display` — тобто **власні токени стають частиною системи утиліт**, а не окремим CSS.

## Що змінилось у компонентах

Жодного файлу `.css` на компонент — усе оформлення класами прямо в JSX:

```jsx
<header className="bg-brand text-white px-6 py-8 rounded-2xl shadow-lg sm:px-10">
```

- **макет:** `flex`, `flex-col`, `grid`, `gap-6`, `lg:grid-cols-[1fr_320px]`
- **відступи:** `px-6`, `py-8`, `mt-2`, `pl-5`
- **типографіка:** `text-3xl`, `font-semibold`, `tracking-tight`, `uppercase`
- **межі й тіні:** `rounded-2xl`, `border border-slate-200`, `shadow-sm`, `divide-y`
- **стани:** `hover:bg-brand`, `hover:text-white`, `hover:-translate-y-0.5`, `hover:shadow-md`, `transition`
- **адаптивність:** `sm:px-10`, `md:grid-cols-2`, `lg:grid-cols-[1fr_320px]` — мобільний вигляд за замовчуванням, брейкпоінти додаються зверху (mobile-first)

Перевірка: `npm run build` генерує ~16 kB CSS — це лише ті утиліти, які реально зустрілись у JSX.

## Питання для самоконтролю (Частина 2)

**1. Різниця між Tailwind і Bootstrap/Material UI.**
Bootstrap і MUI дають **готові компоненти** (кнопка, навбар, модалка) з власним дизайном — швидко, але всі сайти схожі, а кастомізація означає боротьбу з чужими стилями. Tailwind дає **низькорівневі утиліти** (`flex`, `p-4`, `bg-brand`) — жодного готового вигляду, повна свобода дизайну без виходу з розмітки, ціною довших рядків `className`.

**2. Як плагін `@tailwindcss/vite` спрощує налаштування.**
Раніше треба було: `npx tailwindcss init -p` → `tailwind.config.js` із масивом `content` (шляхи для сканування) → `postcss.config.js` → три директиви `@tailwind` у CSS. Плагін для Vite прибирає все це: він сам вбудовується у збірку, сам знаходить файли й сам генерує CSS. Лишається один рядок у `vite.config.js` і один `@import` у CSS.

**3. Що робить `@import "tailwindcss";`.**
Підключає весь Tailwind: нормалізацію (preflight), шар компонентів і генератор утиліт. Збирач при обробці цього рядка сканує вихідний код, знаходить використані класи й підставляє **тільки їх** — тому фінальний CSS маленький.

**4. Як застосувати псевдокласи в Tailwind.**
Через префікси-варіанти перед класом: `hover:bg-brand`, `focus:outline-none`, `focus-visible:ring-2`, `active:scale-95`, `disabled:opacity-50`, `first:mt-0`, `last:mb-0`, `even:bg-slate-50`, `group-hover:text-white`. Їх можна комбінувати з брейкпоінтами: `md:hover:shadow-lg`.

**5. Як налаштувати власні токени дизайну у Tailwind v4.**
Директивою `@theme` прямо в CSS (замість `theme.extend` у `tailwind.config.js` з v3). Оголошена змінна `--color-brand: #4c2a86;` автоматично породжує утиліти `bg-brand`, `text-brand`, `border-brand`, `fill-brand`. Аналогічно `--font-*`, `--spacing-*`, `--radius-*`, `--breakpoint-*`.
